# Marlowby

Concept website for **Marlowby**, a monthly subscription box of local products, small businesses and experiences from a different U.S. city each month. Built for a student web design competition.

**Live site:** https://gopsmonkey.github.io/marlowby/

## Pages
`index.html` (home), `how-it-works.html`, `plans.html`, `cities.html`, `about.html`, `faq.html`, `join.html`, `search.html`, `credits.html`, `404.html`

## Run it locally
It's a static site with no build step needed to view it:

```bash
python3 -m http.server 8743
```

Then open http://localhost:8743. Opening the files directly also works, but the 3D scenes load best from a server.

## Editing
The HTML pages are generated by `tools/build.py`. Edit the page content there, then rebuild:

```bash
python3 tools/build.py .
```

- `css/styles.css`: design system (colors, tiles, header, forms, footer)
- `css/home.css`, `css/pages.css`: home page and Cities/About page styles
- `css/type.css`: font roles
- `js/scene.js`: three.js scenes (balloon box drop, shelf room, rendered box photos)
- `js/main.js`: menu, scroll motion, carousel, map, quiz, forms
- `DESIGN.md`: design rules, motion specs and sources of inspiration

## Everything is served from this repo
No CDN, no webfont request, nothing fetched from another domain. NLC gives you
no internet on site, so the fonts (`vendor/fonts`) and the three libraries
(`vendor/js`: three.js, GSAP with ScrollTrigger, Lenis) ship with the site. Open
the pages with the network off and the 3D scenes, product images, motion and
search all still work.

## Generated files
`tools/build.py` also writes `sitemap.xml`, `robots.txt` and
`search-index.json`. The search index is built from the finished pages, so the
site search can never fall out of step with the copy. Do not edit these by
hand; rebuild instead.

Sources, licenses and the AI usage citation are on `credits.html`.

## Offline and installable
`sw.js` (generated from `tools/sw.template.js` by the build) caches all 65 files
on the first visit. After that the live site keeps working with the network
off, and it can be added to a home screen like an app (`manifest.webmanifest`).
The precache list is read from the built pages, and the build stops if a page
references a file that does not exist.

## Product photos
The box photos are rendered by the site's own three.js code, once, and saved
to `img/shots/` as WebP. After changing a box, a plan size or the route:

```bash
npm --prefix tools/render install   # one time
sh tools/render-shots.sh
```

## City pages and skylines
`tools/build.py` writes one page per route city (`city-savannah.html` and so on)
from `CITIES` and `CITY_INFO`: the box, a box-opening scene with that city's
skyline, the items, the makers and a few facts. Skylines live in
`js/skylines.js`, one function per city, built from the kit in `js/scene.js`
(boxes, cylinders, cones, domes, extruded outlines, trees and mountains). The
facts are real and should stay checkable; the makers are illustrative.
